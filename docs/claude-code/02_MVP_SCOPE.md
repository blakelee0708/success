# MVP Scope

## Build Target
MVP는 Android-first Flutter 앱이다. 하나의 앱에서 피보호자 모드와 보호자 모드가 분기된다.

## Phase 1: 피보호자 런처 UI
목표: 부모님이 실제로 사용할 수 있는 런처 홈을 만든다.

포함:
- 첫 실행 역할 분기
- 피보호자 온보딩
- `정말 쉬운 화면` / `자세한 화면` 선택
- 기본 앱 버튼 표시
- 큰 버튼 UI
- 버튼 색상 시스템
- 글씨 크기 조절
- SOS 전화 화면 연결
- 가족 연결 진입점
- 원래 화면으로 돌아가기 진입점

제외:
- Supabase 연동
- 결제
- 위치
- 통화 감지
- 앱 설치 감지
- 약 알림

## Phase 2: 로컬 설정 구조
목표: 서버 없이도 런처 상태를 저장하고 변경 가능하게 만든다.

포함:
- 화면 모드 저장
- 홈 앱 목록 저장
- 앱 버튼 이름 수정
- 앱 버튼 순서 변경
- 앱 버튼 색상 변경
- 글씨 크기 저장
- 설정 바로가기 모델

## Phase 3: 보호자 대시보드 UI
목표: 보호자가 부모님 폰을 관리하는 화면을 구현한다.

포함:
- 홈 관리 탭
- 메시지 탭
- 안심 탭
- 설정 탭
- 부모님 상태 카드
- 가족 연결 관리 UI
- 부모님 폰 다시 연결 UI
- 가족 보호자 초대 UI
- 가족 플랜용 부모님 전환 UI

## Phase 4: Supabase Data Model
목표: 계정, 프로필, 기기, 연결, 메시지, 홈 설정을 서버 모델로 연결한다.

포함:
- guardian_account
- senior_profile
- senior_device
- guardian_senior_link
- home_apps
- messages
- recovery_links

## Phase 5: 가족 연결 / 복구
목표: 보호자와 피보호자 폰을 안전하게 연결하고 복구한다.

포함:
- 4자리 연결 코드
- 설치 초대 링크
- 부모님 폰 다시 연결
- 일회용 복구 링크 또는 6자리 복구코드
- 기존 기기 자동 해제
- 대표 보호자 변경

- 5분 주기 백그라운드 갱신 — 인터페이스만. 포그라운드 서비스가 필요하다

## Global Non-Goals
- 모든 기능을 한 번에 구현하지 않는다.
- 서버 연동 전에는 repository/interface만 분리하고 mock으로 진행한다.
- Android 정책 리스크가 큰 기능은 UI와 인터페이스 먼저 만들고, 실제 권한 구현은 별도 Phase에서 한다.
